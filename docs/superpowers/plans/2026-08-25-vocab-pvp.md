**Goal:** Real-time PvP vocabulary quiz battles — join-by-code rooms hosted in a new
`GameRoom` Durable Object, playable from the mobile app and the web, with results feeding
mastery/garden/assignments and a monthly PvP ladder — plus a network-free tabletop 1v1
face-off mode on the teacher's tablet (split screen, far half rotated 180°).

**Architecture:** A room = one `GameRoom` DO instance (`idFromName('t:<tenantId>:<code>')`,
WebSocket Hibernation API, same pattern as `workers/live-hub.ts` but bidirectional). The
Worker builds the quiz questions server-side (answers never sent to clients until reveal),
inits the DO, and hands players a 4-letter code. Each client posts its own standard
`GameResult` through the existing result paths (mobile outbox / web `record-result`
intent) so mastery, garden and assignments work with zero new server logic; the DO alone
writes the authoritative `pvp_matches` rows the ladder aggregates.

**Tech Stack:** Cloudflare Durable Objects (SQLite-backed, Hibernation), React Router 7
resource routes, Drizzle/D1, React Native built-in WebSocket (no native modules —
OTA-shippable), shared pure logic in `shared/logic/`.

**Spec:** `docs/superpowers/specs/2026-08-25-vocab-pvp-design.md` — read it first. The
spec is the binding authority; this plan is its argument.

```ts
import type { QuizQuestion } from './flashcards';

export type PvpPlayerKind = 'staff' | 'student';
export type PvpPlayer = { id: string; kind: PvpPlayerKind; name: string };
export type PvpStanding = { id: string; name: string; score: number; correct: number };

export type WireQuizQuestion = {
  wordId: string;
  prompt: 'text' | 'audio' | 'image';
  /** The word to show (text) or speak via TTS (audio); '' for image prompts. */
  promptText: string;
  /** Origin-relative `/flashcard-images/...` path; image prompts only. */
  imagePath: string | null;
  options: string[]; // 4, pre-shuffled server-side
};

export type RoomConfig = {
  topicId: string;
  topicName: string;
  slug: string;
  mode: 'quiz';
  secondsPerQuestion: number; // default 20
  totalQuestions: number;
};

export type ClientMsg =
  | { type: 'start' } // host only, lobby only
  | { type: 'answer'; index: number; option: string };

export type ServerMsg =
  | { type: 'lobby'; code: string; config: RoomConfig; players: PvpPlayer[]; hostId: string }
  | { type: 'question'; index: number; total: number; deadline: number; question: WireQuizQuestion }
  | { type: 'reveal'; index: number; answer: string; correctIds: string[]; standings: PvpStanding[] }
  | { type: 'finish'; standings: PvpStanding[] }
  | { type: 'room-error'; code: 'not_found' | 'already_started' | 'full' | 'not_host' };

export const PVP_CODE_ALPHABET = 'ABCDEFGHJKMNPQRSTUVWXYZ23456789'; // no I/L/O/0/1
export const PVP_CODE_LENGTH = 4;
export const PVP_MAX_PLAYERS = 40;
export const PVP_DEFAULT_SECONDS = 20;
export const PVP_REVEAL_MS = 4000;
export const PVP_LADDER_WIN_POINTS = 3;
export const PVP_LADDER_PLAY_POINTS = 1;
export const PVP_LADDER_DAILY_CAP = 10; // counted matches per student per ICT day

/** Points for a CORRECT answer: 500 base + up to 500 speed bonus. Wrong = 0 at call site. */
export function speedPoints(msLeft: number, msTotal: number): number;
// = 500 + Math.round(500 * clamp(msLeft, 0, msTotal) / msTotal)

/** Split one built quiz question into what clients may see and the answer the DO keeps. */
export function toWireQuiz<
  W extends { id: string; word: string; meaningVi: string; definitionEn?: string | null; imageKey?: string | null },
>(q: QuizQuestion<W>): { wire: WireQuizQuestion; answer: string };
// prompt 'text'/'audio' → promptText = q.word.word, imagePath = null
// prompt 'image'        → promptText = '', imagePath = imageOf(q.word) (never null here)

export type PvpView =
  | { phase: 'connecting' }
  | { phase: 'lobby'; code: string; config: RoomConfig; players: PvpPlayer[]; hostId: string }
  | { phase: 'question'; index: number; total: number; deadline: number; question: WireQuizQuestion; config: RoomConfig; myAnswer: string | null }
  | { phase: 'reveal'; index: number; answer: string; correctIds: string[]; standings: PvpStanding[]; config: RoomConfig }
  | { phase: 'finish'; standings: PvpStanding[]; config: RoomConfig }
  | { phase: 'error'; code: string };

/** Pure reducer — the ONLY place a ServerMsg becomes UI state, shared by web and mobile. */
export function applyServerMsg(view: PvpView, msg: ServerMsg): PvpView;
// 'question' resets myAnswer to null and carries config forward from the previous view;
// unknown msg types return view unchanged (forward compat).

export type LadderRow = { studentId: string; name: string; points: number; wins: number; played: number };

/** Monthly ladder math. Farm resistance without Elo: per student per ICT day, only the
 *  first PVP_LADDER_DAILY_CAP matches (chronological) count. Rank 1 → 3 pts, else 1.
 *  Sorted points desc, then wins desc, then name. Revisit with Elo if farming appears. */
export function ladderFromMatches(
  rows: { matchId: string; playedAtIct: string /* YYYY-MM-DD */; studentId: string; name: string; rank: number }[],
): LadderRow[];

/** The standard GameResult a client posts after a match, built from what it saw revealed. */
export function myResultFromReveals(
  reveals: { index: number; correct: boolean; wordId: string }[],
  durationMs: number,
): { mode: 'quiz'; score: number; total: number; durationMs: number; answers: { wordId: string; correct: boolean }[] };

// ---- Tabletop face-off (same-device 1v1; see the spec's face-off decision) ----

export const FACEOFF_TARGET = 5; // first to 5 points wins
export const FACEOFF_MAX_QUESTIONS = 13; // 2*TARGET + 3: enough for a 4-4 endgame

export type FaceoffSide = 1 | 2;
export type FaceoffState = {
  qIndex: number;
  scores: { 1: number; 2: number };
  /** A wrong tap locks that side out until the next question (anti spam-tapping). */
  locked: { 1: boolean; 2: boolean };
  finished: boolean;
  /** Set when finished; null while running AND on a finished draw. */
  winner: FaceoffSide | null;
};

export function newFaceoff(): FaceoffState;
// { qIndex: 0, scores: {1:0,2:0}, locked: {1:false,2:false}, finished: false, winner: null }

/** Pure reducer for one tap. Ignores input when finished or when that side is locked.
 *  correct → +1 to that side; reaching FACEOFF_TARGET finishes with that winner, else
 *  advance (qIndex+1, both unlocked). wrong → lock that side; both locked → advance with
 *  no point. qIndex reaching totalQuestions finishes on the higher score (tie → winner
 *  null = draw). */
export function faceoffAnswer(
  s: FaceoffState,
  side: FaceoffSide,
  correct: boolean,
  totalQuestions: number,
): FaceoffState;
```

- [ ] **Step 1:** Write the DO, cloning `LiveHub`'s hibernation discipline verbatim:
  constructor calls
  `this.ctx.setWebSocketAutoResponse(new WebSocketRequestResponsePair('ping','pong'))`;
  sockets accepted with `this.ctx.acceptWebSocket(server)` (never `server.accept()`);
  per-socket identity in `serializeAttachment({ userId })` (2 KB cap); handlers are class
  methods; every piece of room state lives in `ctx.storage` because the constructor
  re-runs on every wake. Storage keys:
  - `room`: `{ code, tenantId, hostId, config: RoomConfig, phase: 'lobby'|'question'|'reveal'|'done', qIndex: number, createdAt: string }`
  - `questions`: `{ wire: WireQuizQuestion; answer: string }[]` — answers exist ONLY here
  - `players`: `Record<userId, { name: string; kind: PvpPlayerKind; score: number; correct: number; joinedAt: string }>`
  - `answers:<qIndex>`: `Record<userId, { option: string; ms: number /* epoch when received */ }>`

  `fetch(request)` routes on pathname:
  - `POST /init` — body `{ code, tenantId, hostId, config, questions }`. If a stored
    `room` exists with `phase !== 'done'` and `createdAt` younger than 2h → 409
    `{ error: 'room_exists' }`. Otherwise wipe storage, store everything, register the
    host as the first player (name/kind ride in the body as `host: PvpPlayer`), set the
    2h expiry alarm. → 200.
  - `GET /connect` — must be a websocket upgrade (else 426). Identity from headers
    `X-Game-User`, `X-Game-Kind`, `X-Game-Name` (`decodeURIComponent`), set by
    `handleGameUpgrade` (clients cannot spoof them — the handler overwrites). No stored
    room → 404. Unknown user while `phase !== 'lobby'` → 409. Lobby full
    (`PVP_MAX_PLAYERS`) → 403. Otherwise accept, attach, add the player if new,
    broadcast a fresh `lobby` to every socket. A KNOWN player reconnecting mid-game is
    accepted and immediately sent the current `question` (with the original deadline) or
    `reveal` so they land in the running game.
  - `webSocketMessage(ws, raw)` — `JSON.parse` inside try/catch, ignore garbage. On
    `{type:'start'}`: sender must be `hostId` (else send `room-error not_host`), phase
    must be `lobby` with ≥2 players (else ignore); set phase `question`, qIndex 0,
    broadcast question 0 with `deadline = Date.now() + config.secondsPerQuestion * 1000`,
    `ctx.storage.setAlarm(deadline)`. On `{type:'answer', index, option}`: ignore unless
    phase is `question` and index === current qIndex and the user hasn't answered this
    index; record `{ option, ms: Date.now() }`; if every player has now answered, run the
    reveal step immediately (and `deleteAlarm`).
  - **Reveal step** (from alarm or early-advance): for each recorded answer equal to the
    stored `answer`, add `speedPoints(deadline - ms, config.secondsPerQuestion * 1000)`
    to that player's score and increment `correct` (the stored deadline for the current
    question must be persisted alongside `room` when the question is broadcast — store it
    as `room.deadline`). Broadcast `reveal` with `correctIds` and standings (sorted
    score desc, tie-break correct desc, then name). Phase → `reveal`;
    `setAlarm(Date.now() + PVP_REVEAL_MS)`.
  - **Next / finish** (alarm while phase `reveal`): if `qIndex + 1 < questions.length`,
    advance qIndex, broadcast the next `question` (fresh deadline, setAlarm as above);
    else broadcast `finish`, persist the match (below), phase → `done`,
    `setAlarm(Date.now() + 60_000)` to close remaining sockets.
  - **Persist on finish:** `createRawDb(this.env)` (from `server/db/internal`) + drizzle:
    insert one `pvpMatches` row (`id: crypto.randomUUID()`, tenantId/code/topicId from
    room state, `mode: config.mode`, `played_at: new Date().toISOString()`) and one
    `pvpMatchPlayers` row per player (`student_id` or `staff_id` by kind, rank from the
    final standings order, score/correct, `total: questions.length`). NO audit call — no
    request context exists in a DO; mirror `setIssueNumber`'s "nobody chose this"
    reasoning in a comment.
  - `alarm()` — branch on stored phase: `question` → reveal step; `reveal` → next/finish;
    `done` → close all sockets (code 1000); lobby older than 2h → wipe storage and close
    sockets (expiry, so an abandoned code frees up).
  - `webSocketClose`/`webSocketError` — same close-echo shape as LiveHub. A disconnect
    does NOT remove the player from `players` (they may reconnect); it only drops the
    socket.

  Head doc comment: why answers never leave the DO; why the DO writes matches but never
  mastery (clients post their own `GameResult` through existing offline-durable paths).

  Also in this file: `handleGameUpgrade(request, env)` — mirrors `handleLiveUpgrade` in
